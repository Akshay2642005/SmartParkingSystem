# Snapshot: v0.1.0 — Specification Baseline

Status: **Planned** (release `v0.1.0`, see `../../planning/RELEASES.yaml`)

This snapshot records the **initial specification baseline**. It describes the
intended system at the point where the specification set is established. It does
not claim that features are implemented unless they exist in the repository.

---

## Scope

The system intends to:

- Detect parking-slot occupancy via ESP32-connected sensors.
- Report device and slot state to a backend platform.
- Persist current state and occupancy history.
- Expose parking availability through a dashboard.
- Simulate device hardware in Wokwi.

See `../SCOPE.md` for the full in/out-of-scope statement.

## Requirements

- Functional requirements are catalogued in `../REQUIREMENTS.md` (FR-001 …
  FR-041).
- Non-functional requirements are catalogued in `../REQUIREMENTS.md`
  (NFR-001 … NFR-008).
- At baseline, all functional capability is `Planned`.

## Architecture Status

| Layer | Status |
| ----- | ------ |
| Firmware | Scaffold: ESP-IDF project boots and prints system info |
| Simulation | Current: Wokwi ESP32 + serial monitor |
| Sensor | Pending Decision (`ADR-0004` Proposed) |
| Connectivity | Pending Decision (`ADR-0005` Proposed) |
| Backend | Scaffold: Rust workspace, no API yet (`ADR-0006` Proposed) |
| Persistence | Pending Decision |
| Dashboard | Scaffold: Next.js default starter (`ADR-0009` Proposed) |

## Known Limitations

- No sensor is connected to the firmware yet.
- No device-to-backend communication exists.
- No backend API or persistence exists.
- No dashboard functionality beyond the starter template exists.
- No real-time update mechanism is chosen.

## Planned Next Milestone

- **M1 — ESP32 Foundation** (see `../../planning/PLAN.md`): firm up the firmware
  structure, sensor selection (`ADR-0004`), and Wokwi simulation with a sensor.
